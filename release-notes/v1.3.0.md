## Highlights & New Features

### 1. Just-in-Time (JIT) / RFC 9396 Step-Up Authorization (`@lumoauth/mcp`, `lumoauth`)

Sensitive MCP tools can now require task-bound RFC 9396 Rich Authorization Requests (`authorization_details`) and emit structured step-up challenges when a human approval is missing:

- Added `InsufficientAuthorizationDetailsError`, `normalizeAuthorizationDetails()`, `authorizationDetailCovered()`, and `missingAuthorizationDetails()` (`packages/mcp/src/tools.ts`).
- Extended `auth.secureTools()`, `auth.guard()`, and `checkToolAccess()` (`packages/mcp/src/tools.ts`) with `jit` requirement specs and `filterList` / `hideJitUntilGranted` options to filter `tools/list` responses and enforce JIT approvals on `tools/call`.
- Extended `LumoMcpAuth` (`packages/mcp/src/auth.ts`) to verify accompanying `X-LumoAuth-Jit-Token` HTTP headers against the organization JWKS and caller subject (`caller.sub` or `caller.actor`), merging verified `authorization_details` into `caller.authorizationDetails` and setting `caller.isJit`.
- Added `--jit <tool>=<type>[:act1,act2]` flag to `lumoauth secure` and `lumoauth ext-authz` (`packages/lumoauth/src/cli.ts`, `packages/lumoauth/src/proxy.ts`, `packages/lumoauth/src/jsonrpc.ts`), returning `insufficient_authorization_details` tool errors and `Insufficient-Authorization-Details` headers on missing approvals.

```ts
import { lumoAuth } from '@lumoauth/mcp';

const auth = lumoAuth();
auth.secureTools(server, {
    scopes: { refund: ['invoices:refund'] },
    jit: {
        wireTransfer: {
            type: 'payment_initiation',
            actions: ['wire'],
            locations: ['https://api.stripe.com'],
        },
    },
});
```

### 2. Token Vault Integration for Outbound SaaS APIs (`@lumoauth/mcp`, `lumoauth`)

MCP tools and upstream servers can now mint short-lived outbound OAuth access tokens (e.g., GitHub, Slack, Jira, Google Workspace) from LumoAuth's Token Vault, automatically scoped to the active MCP caller:

- Added `VaultClient`, `VaultToken`, and `resolveVaultUserId()` (`packages/mcp/src/tools.ts`) and exposed `auth.vault()` / `auth.vaultToken(connectionId, extraOrOptions)` on `LumoMcpAuth` (`packages/mcp/src/auth.ts`):
  - Automatically passes `user_id: caller.sub` when the caller is a human user (`!caller.isAgent`) or a user-delegated agent (`caller.isDelegated`).
  - Caches `VaultToken` entries in memory until 30 seconds before `expiresAt` (`vaultTokenTtl`, default `60s`).
- Added `--vault <slug>=<connection_id>` flag to `lumoauth secure` and `lumoauth ext-authz` (`packages/lumoauth/src/cli.ts`, `packages/lumoauth/src/proxy.ts`, `packages/lumoauth/src/ext-authz.ts`) to automatically inject `X-LumoAuth-Vault-<Slug>-Token` headers into upstream requests.

```ts
server.registerTool(
    'create_github_issue',
    { inputSchema: { repo: z.string(), title: z.string() } },
    async ({ repo, title }, extra) => {
        const gh = await auth.vaultToken('conn_github_prod', extra);
        const response = await fetch(`https://api.github.com/repos/${repo}/issues`, {
            method: 'POST',
            headers: {
                ...gh.headers(),
                Accept: 'application/vnd.github+json',
                'Content-Type': 'application/json',
            },
            body: JSON.stringify({ title }),
        });
        return { content: [{ type: 'text', text: await response.text() }] };
    },
);
```

### 3. Envoy `ext_authz` Server & Kubernetes Sidecar Deployment (`lumoauth`)

- Added `createExtAuthzServer()` (`packages/lumoauth/src/ext-authz.ts`) and the `npx lumoauth ext-authz` CLI subcommand (`--ext-authz`) to run LumoAuth as an Envoy HTTP `ext_authz` external authorization service:
  - Serves RFC 9728 discovery at `/.well-known/*` and `200 OK` on `--public` health paths.
  - Verifies Bearer and DPoP tokens, inspects buffered JSON-RPC `tools/call` bodies (`with_request_body`) for per-tool Zanzibar policy and `--jit` step-up requirements, and returns `X-LumoAuth-*`, `X-LumoAuth-Vault-*-Token`, and `traceparent` headers for Envoy to inject upstream.
- Added production container and deployment manifests:
  - Multi-stage non-root (`65532:65532`) `Dockerfile` with `/healthz` healthcheck.
  - `deploy/kubernetes-sidecar.yaml` for Kubernetes sidecar deployments.
  - `deploy/envoy-ext-authz.yaml` for Envoy `ext_authz` filter integration.

### 4. W3C `traceparent` Distributed Trace Propagation (`@lumoauth/mcp`, `lumoauth`)

- Added `parseTraceparent()` (`packages/mcp/src/auth.ts`) to validate incoming W3C `traceparent` headers (`00-<trace-id>-<span-id>-<flags>`) or JSON-RPC `params._meta.traceparent` values, exposing `caller.traceparent` and `caller.traceId`.
- Automatically forwarded `traceparent` on `ToolPolicy` (`mcp.authorizeTool`) and `VaultClient` requests, and injected `X-LumoAuth-Trace-Id` and `traceparent` headers to upstream MCP servers.
