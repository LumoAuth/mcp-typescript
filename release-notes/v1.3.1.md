## Fixes

### Capability Matching Now Follows the Server Exactly (`@lumoauth/mcp`)

`capabilityCovered()` and the `agents: [...]` option compare agent capabilities in the form that the LumoAuth server stores. The 1.3.0 matcher differed from the server in two ways:

- It lower-cased every letter, but the server lower-cases ASCII letters only. An agent that held `ünits.read` therefore passed a check for `Ünits.Read`, although the server treats them as two different capabilities.
- It trimmed with `String.prototype.trim()`, which strips Unicode spaces but not NUL. The server trims only space, tab, LF, CR, NUL and vertical tab.

Changes in `packages/mcp/src/scopes.ts`:

- `capabilityCovered(required, granted)` now lower-cases ASCII letters only and trims the same characters as the server. Entries of `granted` that are not strings are now ignored.
- Added the `normalizeCapability(capability)` export. It returns a capability in the form that the server stores: trimmed, ASCII letters in lower case, `:` and `-` turned into `.`, runs of `.` collapsed, and `.` trimmed from both ends.

These checks use `capabilityCovered()`, so they follow the new rules too:

- the `agents: [...]` option of `auth.guard()`, `auth.secureTools()` and `checkToolAccess()`
- the `tools/list` filter of `auth.secureTools()`, which hides a tool when the caller fails its local checks

The other rules stay the same: `:` and `-` read as `.`, `*` covers every capability, and `users.*` covers `users.delete` but not `users` itself.

```ts
import { capabilityCovered, normalizeCapability } from '@lumoauth/mcp';

normalizeCapability('Invoices:Read');                   // 'invoices.read'
normalizeCapability('Ünits.Read');                      // 'Ünits.read'
capabilityCovered('tool:search_web', ['tool.search_web']); // true
capabilityCovered('Ünits.Read', ['ünits.read']);        // false (true in 1.3.0)
```

### `lumoauth` CLI

- No code changes besides the version. The CLI now requires `@lumoauth/mcp` `^1.3.1`.
- The `lumoauth secure` and `lumoauth ext-authz` flags do not check agent capabilities, so this fix does not change what the CLI admits.

---

## Upgrade Notes

- **The `agents: [...]` option can now refuse an agent that 1.3.0 admitted.** This happens only when the capability names differ in upper-case non-ASCII letters, or in leading or trailing characters that the server does not trim. With `auth.secureTools()`, such a tool also disappears from that agent's `tools/list`. The new answers match the server's.
- No breaking changes and no dependency changes. `@lumoauth/mcp` still requires `@lumoauth/agent` and `@lumoauth/shared` `^1.2.0`.

## Tests

- Added `packages/mcp/tests/capability-contract.test.mjs`. It runs all cases in `sdk-contract/vectors/agent-capabilities.json` through `normalizeCapability()` and `capabilityCovered()`. The contract repo checks the same cases against the server's own matcher. Set `LUMO_SDK_CONTRACT` to point the test at a contract checkout. Without one, the test is skipped.
- Added two non-ASCII cases to the helper test in `packages/mcp/tests/auth.test.mjs`.
