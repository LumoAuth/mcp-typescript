## Highlights

### 1. Capabilities in `<resource>:<action>` Form (`@lumoauth/mcp`)

An agent capability is one of the agent's OAuth scope values. LumoAuth now writes every capability as `<resource>:<action>`, such as `invoices:read`, with the wildcard `invoices:*`. `normalizeCapability()` and `capabilityCovered()` in `packages/mcp/src/scopes.ts` now follow the server's new rules:

- `normalizeCapability()` returns the server's canonical form, with `:` between the parts. It trims the name, lower-cases ASCII letters, turns every `.` into `:`, collapses runs of `:` and trims `:` from both ends.
- A `-` is now part of a name, not a separator. `pull-requests:comment` is one resource and one action, and `invoices-read` is a different capability from `invoices:read`.
- `*` covers every capability. A name that ends in `:*` covers every action under that prefix, at any depth, but not the prefix itself. `invoices:*` covers `invoices:read` and `invoices:read:draft`, but not `invoices` and not `invoices-archive:read`.
- A `.` is still read as `:` when the package compares. `agents: ['billing.refund']` still admits an agent that holds `billing:*`, and a held `users.*` still covers `users:delete`.
- An exact capability never covers a longer one: a held `web:search` does not cover `web:search_news`.
- Only ASCII letters are lower-cased, as before. `Ünits:Read` becomes `Ünits:read`.

These checks use `capabilityCovered()`, so they follow the new rules too:

- the `agents: [...]` option of `auth.guard()`, `auth.secureTools()` and `checkToolAccess()`
- the `tools/list` filter of `auth.secureTools()`, which hides a tool when the caller fails its local checks

`scopeCovered()`, `missingScopes()` and the `scopes` option did not change. They still compare token scopes exactly, except for a granted scope that ends in `:*`.

| Input to `normalizeCapability()` | 1.3.1 | 1.4.0 |
| :--- | :--- | :--- |
| `'Invoices:Read'` | `'invoices.read'` | `'invoices:read'` |
| `'Invoices.Read'` | `'invoices.read'` | `'invoices:read'` |
| `'invoices-read'` | `'invoices.read'` | `'invoices-read'` |

```ts
import { capabilityCovered, normalizeCapability } from '@lumoauth/mcp';

normalizeCapability('Pull-Requests.Comment');           // 'pull-requests:comment'
capabilityCovered('USERS.DELETE', ['users:*']);         // true
capabilityCovered('users-delete', ['users:*']);         // false (true in 1.3.1)
capabilityCovered('users', ['users:*']);                // false

server.registerTool('send_reminder', { inputSchema: { invoiceId: z.string() } },
    auth.guard('send_reminder', sendReminder, { agents: ['reminders:send'] }));
```

### 2. `lumoauth` CLI

- No code changes besides the version. The CLI now requires `@lumoauth/mcp` `^1.4.0`.
- The flags of `lumoauth secure` and `lumoauth ext-authz` do not check agent capabilities, so this release does not change what the CLI admits.

## Upgrade Notes

- **`normalizeCapability()` returns a different string.** It now returns `invoices:read` where 1.3.1 returned `invoices.read`. Update any code that stores or compares its output.
- **An agent that 1.3.1 admitted can now fail the `agents: [...]` check.** This happens when a name uses `-` where the agent's capability uses `:` or `.`. For example, `agents: ['users-delete']` no longer admits an agent that holds `users:*`. With `auth.secureTools()`, such a tool also disappears from that agent's `tools/list`. Write these names as `<resource>:<action>`.
- **Write capabilities as `<resource>:<action>`.** LumoAuth refuses the dot form (`invoices.read`) when you register an agent's capability. Names in the `agents: [...]` option may still use the dot form, because the check reads a `.` as `:`.
- **`caller.capabilities` holds the capabilities exactly as the token carries them.** The package does not rewrite them. A held `web:search` stays `web:search`, so `caller.capabilities.includes('web.search')` is `false`. Use `capabilityCovered()` to match by the server's rules.
- **You don't need a newer SDK.** The matching rules are in `@lumoauth/mcp` itself. The package still requires `@lumoauth/agent` and `@lumoauth/shared` `^1.2.0`, and Node.js 20 or later. No other dependency changes.

## Documentation & Tests

- The `agents` example in `packages/mcp/README.md` now uses `reminders:send`. It also explains the `<resource>:<action>` form and the `reminders:*` wildcard.
- The doc comments of `normalizeCapability()` and `capabilityCovered()` now describe the new rules.
- `packages/mcp/tests/auth.test.mjs`:
  - The agent-token test now uses the capability `billing:*`.
  - The helper test has new cases for the dot spelling, the `-` rule, `users-archive:read` and the prefix itself. The non-ASCII cases now use the `:` form.
- `packages/mcp/tests/capability-contract.test.mjs` runs the shared cases in `sdk-contract/vectors/agent-capabilities.json`, which are now in the `<resource>:<action>` form. The test reads the contract from `LUMO_SDK_CONTRACT` or from an `sdk-contract` checkout next to this repository. Without either, the test is skipped.
- At the tag, all 36 `@lumoauth/mcp` tests and all 18 `lumoauth` tests pass, with the contract test included.
- Added the release notes for v1.3.1 (`release-notes/v1.3.1.md`).
